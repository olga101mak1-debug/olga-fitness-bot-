## ⚠️ Важно: деплой вручную по SFTP, не через git

- Деплой на сервер идёт вручную по SFTP (paramiko), НЕ через `git pull`.
- Из-за этого правки, сделанные прямо на сервере, могут не попадать обратно в этот GitHub-репозиторий, если их отдельно не закоммитить и не запушить.
- **Подтверждено 23.07.2026:** фикс `max_tokens` (500→2000 в `coach.py`/`weekly_analyst.py`) стоит на сервере, но в этом репозитории всё ещё старое значение — значит, после серверного фикса коммит в GitHub не был сделан.
- Правило на будущее: после любой правки прямо на сервере — обязательно скачать актуальный файл и закоммитить его сюда же, иначе следующая сессия будет работать со устаревшим кодом.

### 2026-07-23 — Баги пустых/неверных ответов исправлены на сервере

- Факт: три независимых бага исправлены на проде 23.07.2026— (1) пустой ответ Claude не отправлялся с fallback-сообщением, (2) `max_tokens=500` было мало для сложных аналитических запросов → 0 текстовых блоков → пустой ответ, исправлено на 2000, (3) `_format_context()` не включал обхваты тела (`waist/belly/hips/neck/chest`) в тренд → бот врал, что таких данных нет.
- Почему важно помнить: это не одна проблема, а три независимых, наложившихся на один и тот же тип запроса («сравни все показатели за неделю»). При похожих жалобах — проверять все три места, не останавливаться на первой найденной причине.
- Где связано: `bugs-and-gotchas.md`, раздел «⚠️ Важно» выше (фикс мог не попасть в этот репозиторий)

### 2026-09-02 — Реальная картина по данным на момент переделки

- Факт: вес 88.2 (15.02) → 76.3 (28.08), цель 69. Но за последние 30 дней +0.1 кг, темп
  -0.11 кг/нед — плато. Белок в среднем 45 г при норме 135, норма не взята ни разу за 30 дней.
  Еда записана 10 дней из 30, вес — 13 из 30. При этом талия -2 см и живот -4 см за месяц.
- Почему важно помнить: это отправная точка. Если через месяц цифры дисциплины не выросли,
  проблема не в аналитике, а в том, что дневник не ведётся — и говорить надо об этом.
- Где связано: `decision-log.md` → «Тон бота»

### 2026-09-02 — Схема базы обновляется автоматически при старте

- Факт: `engine._sync_columns()` дописывает в существующие таблицы колонки, появившиеся в моделях
  (`create_all` этого не делает — он создаёт только отсутствующие таблицы целиком).
- Почему важно помнить: новое поле в `models.py` доедет до прода само при рестарте сервиса,
  вручную ALTER TABLE делать не нужно. Данные при этом не теряются: у старых строк будет NULL.
- Где связано: `bugs-and-gotchas.md`
