# Spec: правки A–D в LIFE AI (дубли фото, контекст, память диалога, еда словами)

Дата постановки: 2026-07-29. Основание — разбор переписки с ботом за 29.07.2026.

## Что чиним

**A. Дубли на альбоме фото.** Сейчас `photos.py` обрабатывает каждое фото альбома отдельно →
два ракурса одного йогурта = два приёма пищи (25 + 250 ккал), два скрина тренировки = две записи
«силовая» + два поздравления.

**B. Коуч не видит день.** В `coach.py` уходит только `daily_log` + тренд + цель + инсайты.
Не уходят: съеденное сегодня, тренировки сегодня, текущее время → «завтрак лёгкий» в 13:49
и совет ехать в зал после уже состоявшейся тренировки.

**C. Нет памяти диалога.** Бот не хранит переписку → в 13:49 отвечает на утренний вопрос про зал,
повторяет одно и то же (ответы 7:42 и 7:44 дублируют друг друга).

**D. Еда словами не считается.** В `parser.py` нет полей про еду → вафля/банан/клубника/яичный кофе
из голосового не попали в дневной итог, белок «13.4 из 135» занижен, и на этой цифре строятся советы.

## Критерии готовности

1. Альбом из N фото → **ровно один** ответ бота и **ровно одна** запись в БД
   (один приём пищи или одна активность), информация с разных ракурсов объединена.
2. Одиночное фото работает как раньше (один ответ, одна запись).
3. В контекст коуча попадают: текущее время, приёмы пищи за сегодня с итогами,
   активности за сегодня, последние сообщения переписки за сегодня.
4. Переписка (входящие пользователя и ответы бота, включая ответы на фото и утреннее/вечернее
   сообщение планировщика) сохраняется в БД и переживает перезапуск сервиса.
5. Еда, описанная текстом или голосом, попадает в приёмы пищи с оценкой ккал/БЖУ,
   дневной итог пересчитывается, в ответе есть строка «🍽 Записала: …».
6. Поправка к последнему приёму пищи («порция больше») продолжает работать.
7. Новая таблица создаётся на существующей боевой БД без потери данных.
8. Сервис `lifeai.service` на EU VPS поднимается и остаётся `active` после деплоя, в логах
   нет ошибок импорта/инициализации.

## Как проверяется

- Синтаксис/импорты: компиляция всех модулей.
- Пункты 1–2, 5–6: офлайн-прогон логики на временной копии БД с подменёнными вызовами Claude
  (без обращения к API и Telegram) — считаем записи в БД и количество ответов.
- Пункт 3: сборка контекста коуча на тестовых данных, проверка наличия блоков в тексте промпта.
- Пункты 4, 7, 8: после деплоя — `systemctl status`, `journalctl`, проверка таблиц в боевой БД
  и реальный обмен сообщениями с ботом.

## Что НЕ входит

- Чистка уже задвоенных записей за 29.07.2026 (делается отдельно, по подтверждению, с бэкапом БД).
- Смена модели, переписывание тона ответов, новые команды меню.
